# 沉浸式露营剪辑

让观众跟着人物进入一个地方，看见生活逐步安顿下来，再有时间感受劳动之后的舒适、人与环境的相处。依据本期实际发生的事建立过程，把可理解的动作、可感知的声音和自然的人物表达组织成完整体验。

## 决策主干

1. **先看发生了什么。** 按源时间区间识别人物、动作与变化，检查整条素材；同一文件可以承担多个叙事作用。
2. **让每个保留镜头有作用。** 推进事件、交代空间、呈现感官细节或容纳情绪停留。相同信息已经充分表达时压缩重复，新的变化或值得感受的细节继续保留。
3. **让重要动作可读。** 保留理解动作所需的起因、关键执行与结果；结果刚出现时留出辨认时间。重复劳动可省略，关键变化要看清。
4. **给生活留出落点。** 在重要准备过程之后寻找使用、享用、休息或环境中的停留；以实际素材形成回报，允许小过程独立成篇。
5. **先确定观众此刻看什么、听什么。** 稳定构图承载动作，原声建立触感和空间，音乐承担明确的情绪或时间压缩任务，文字带出情境、人物与前后关系。
6. **按作用处理冲突。** 先满足真实、动作可读和观看舒适，再选择气氛、装饰和时长。漂亮镜头也需承担作用；缺少稳镜头时调整段落，缺少某阶段时按已有事件收束。

详细判断见 [风格规则](references/style-guide.md)。固定观看方式与视觉规范；人物、地点、装备、天气、是否过夜、事件顺序和片长由本期素材决定。

## 开始工作

读取风格规则，从消息取得素材位置、目标和已给约束。只有素材位置缺失、文件不可读或关键意图确实无法判断时提问；片长、标题与技术选项根据素材判断并简短说明。原素材只读，分析与中间文件放在独立任务目录的 `work/`，跨轮次从已有记录继续。

默认先完成全片可编辑粗剪与审片 MP4，交给用户修改；用户要求首次交付带调色时一并完成。用户要求只分析、只要 MP4、指定其他软件或一次完成时，按其目标调整范围。人工修改后的修订以最新工程为依据。

## 从素材到成片

### 1. 识别候选区间

扫描全部媒体，保存素材清单与错误。按拍摄时间形成候选顺序，再用画面确认事件关系。生成带源时间码的接触表并实际查看；长片覆盖所有时段，再加密检查主体入场、动作变化和结果。文件名、首帧与稀疏抽帧仅用于定位。

在 `shot-log.json` 记录每个候选的源 ID、入出点、事件、时段、景别、作用、动作、结果、声音和稳定性状态，以及实际检查证据。作用可用 establishing、action、detail、result、enjoyment 或 transition；仅记录素材确实承担的作用。

按复核标准连续检查完整拟用区间及切点附近。优先换同作用的稳镜头，再找动作成立的稳定子区间；需要防抖时先验证短片处理效果。缺少连续审看能力时，候选保持 `unreviewed`，继续素材分析与暂排，交付标明待稳定性复核。

### 2. 建立事件与声音关系

为每个主要事件写清“开始时的状态 → 发生的变化 → 结束时的状态”，标出对应源区间及观众需要知道的信息。按因果和实际时间排列，压缩重复准备，保护关键动作，并为重要过程寻找生活上的落点。

在 `edit-notes.md` 保存事件链、选镜理由及取舍。遇缺失环节，先找相关素材，再通过已有线索缩短、合并或省略。每处场景或时段变化写清前后镜头的空间、动作或时间联系。

同时规划值得保护的现场声音，以及有依据的情境、选择、变化和人物旁注。按段落安排文字与留白，使用声音和画面已经讲清的信息继续向前推进。

### 3. 完成粗剪

先建立正文，再决定开场。直接进入环境和首个有意义动作即可；需要预告时，仅选能建立本期期待的不同体验，回到正文后继续推进。片头身份、地点和必要信息叠在真实动作中，按 [介绍规则](references/style-guide.md#实拍中的片头与信息介绍) 使用可编辑图层。

根据动作可读性与观看需要确定入出点。关键变化清楚、结果被感知后再切；重复步骤以有信息的省略推进。安静停留保留能持续感受的声音、互动、光线或空间关系。变速只用于有明确作用且仍能理解的区间。

先渲染一个覆盖主要动作、声音和文字的代表段落，自查构图、动作与阅读节奏，再继续全片。仅在用户明确要求先看样片时停在样片。

### 4. 落实声音、文字与颜色

先建立可听的动作声和环境底声，再决定音乐的段落目的、进入与退出位置。在 `audio-plan.json` 或 cue 表记录曲目来源与授权、源和成片区间、保护声音、增益、淡化及实现状态。连续原声本身是一种完整段落选择。缺少可用音乐时先交付原声审片版与待配乐方案。

按 [字幕与文案](references/style-guide.md#字幕与文案) 写有依据、有人物在场的日记旁注。每句承担理解、人物或叙事作用；在完整动作和安静享用间留出无字观看空间。先在本期实际画面校准样式，再应用到独立字幕对象。介绍层另存 `intro-plan.json`，核对内容、位置、动效和跨镜阅读。

调色先解决曝光、白平衡和色偏，再匹配相邻镜头，保留昼夜光线与现场暖意。需要调色时按调色文档校准代表画面，再逐镜处理；默认写入视频片段自身的原生调整参数，独立调节轨道按用户要求采用。原生工程和配置渲染各自验证实际效果。

### 5. 验收与交付

按时间线格式保存源 ID、源区间、剪点、速度、声音、字幕和构图。默认先把全片落实到剪映可编辑工程，再完成审片导出。按复核标准连续检查事件边界、动作结果、稳定性、文字、配乐出入与结尾，并完成技术解码检查。

分别记录技术检查、连续画面检查和实际听审。抽帧、波形与机器分类只支持对应检查，未完成部分标明区间和下一步。工程需要在目标版本打开、保存、退出并重开；完成这些检查后再标记工程交付成功。

交付可编辑工程与草稿备份、审片 MP4、FCPXML、可编辑字幕、素材映射、`timeline.json`、`edit-notes.md`、`review.md` 和成片接触表。配乐与介绍任务同时交付对应计划；配置渲染保留 `.render.json`。在记录中关联源时间与成片时间、工具版本、运行命令、工程和 MP4 的实际差异，说明外部素材依赖。

工程工具不可用时保留已经完成的分析、时间线和审片成果，说明具体阻塞及工程待完成项。修改采用下一版本，用户人工修改后按协作交接继续；本期事件和参数留在本期记录，跨素材成立且经用户确认的偏好再更新为通用规则。
