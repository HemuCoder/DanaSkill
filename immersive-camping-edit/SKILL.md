# 沉浸式露营剪辑

把素材组织成观众能跟着经历的生活过程。让一个地方逐渐成为可居住的空间，让劳动之后有使用和享用的落点。

## 开始工作

1. 读取 [风格规则](references/style-guide.md)，查看 [参考画面](assets/reference-board.jpg)。本 Skill 已携带必要参考，新会话可独立使用。
2. 根据用户目标选择工作范围：剪新片、只分析、修改现有片或复核。新一期默认先完成可编辑剪映粗剪与审片视频，交给用户修改；收到已保存并开始调色的指令后，按 [协作交接](references/collaboration.md) 从最新工程继续。用户要求首次交付带调色时，在初始工程交付前验证并写入视频片段自身的原生调整参数；首次写入与人工修改后的回读、回写分别验证。用户要求一次完成、只要 MP4、只分析或指定其他软件时，按其要求执行。
3. 从消息中读取素材路径和已给约束。只有素材位置缺失、文件不可读或必须由用户决定的信息才提问。总时长、标题和技术选项可按素材作合理判断并简短说明。
4. 使用 [运行方法](references/runtime.md) 准备工具、工作目录与素材清单。原始素材保持只读，处理结果写在独立任务目录。
5. 在 `work/` 保存进度、清单、候选时间段、时间线和日志；在当前会话指定的输出目录交付用户文件。跨轮次从已有记录继续。
6. 剪片任务默认读取 [剪映工程](references/jianying-project.md)，以本机 Mac 剪映可编辑工程为主交付。镜头、原声、字幕分别保留可调整对象，引用现有原片；采用官方导入通路并完成打开、保存、退出和重开验证。无需再次询问是否需要工程；用户已明确指定其他交付时遵从。

用户人工修改后的工程是后续调色的剪辑依据。保留其素材、剪点、字幕、特效与构图；旧时间线只作历史快照。用户明确确认剪辑未改并要求按原交付基线继续时，核对基线、备份当前工程后可据此生成颜色版本；这不代表已回读最新编码工程。分别验证首次原生片段参数写入、最新工程回读和修改后回写，按实际结果报告能力。

## 固定的剪辑判断

- 以真实事件和动作的因果关系组织画面。先交代整体，再看关键操作，最后看完成状态或人物享用；素材允许时交替景别。
- 稳定、舒适的观看是选镜条件。按 [稳定性筛选](references/review.md#稳定性筛选与验收) 连续检查拟用区间，剔除明显手抖、机位碰撞及启停晃动；保留自然做事的人、清楚的手部细节和可理解的空间关系。
- 按源时间区间识别事件，保留动作的触发、关键执行和落点。车辆可能在风景镜头后半段才驶入，须检查整条素材中的事件变化；把到达过程剪清楚，再压缩等待。
- 完成任务后，给成品、休息、饮用、用餐或营地全景一点时间。
- 用生活动作、同地点光线和空间关系连接开场、入夜与次晨；按 [时段衔接](references/style-guide.md#时段衔接) 建立前后关系，再选择剪法。
- 让原声承载动作和环境，按 [配乐与原声](references/audio/music-direction.md) 安排舒缓音乐的进入、退出和连续原声区间。音乐服务于事件与情绪，镜头继续服从动作。
- 按 [字幕与文案](references/style-guide.md#字幕与文案) 写具体、自然、稀疏的旁注。每句既要有事实依据，也要提供画面之外的理解；无新增信息就留白。中文正文默认小号常规无衬线白字、贴字半透明黑底、底部安全区；工程与审片版都须落实该样式。
- 把结尾放在自然成立的状态。可以坐下来继续享受，也可以按实际素材收营返程。

装备、人数、饭菜、节日、地点、总时长和是否过夜由本期素材决定。准确镜头秒数、搭建所占比例和配乐位置均属于可调整选择。

## 从素材到成片

### 1. 检查和理解素材

扫描文件并记录视频、音频、图片及错误。按拍摄时间形成候选顺序，再用画面判断真实事件；文件名和创建时间仅作线索。

对每个视频生成有源时间码的接触表，实际查看画面。长片先粗看全部时段，再对有用事件加密抽帧和检查动作起止。快速动作、相机启停、多人接力、近似机位要进一步核对；抽帧不能证明动作连续、稳定性、速度或声音。拟入选镜头须按 [稳定性筛选](references/review.md#稳定性筛选与验收) 检查完整源区间及切点附近，先解决晃动再确定入出点。

在 `shot-log.json` 为候选片段记录：

```json
{
  "source": "稳定素材ID",
  "in": 12.4,
  "out": 20.8,
  "event": "固定天幕",
  "time_of_day": "day",
  "scale": "wide",
  "role": "action",
  "action": "拉紧绳索并固定",
  "result_visible": true,
  "audio": "unreviewed",
  "stability": "unreviewed",
  "motion_review": null,
  "quality": "pending",
  "evidence": "仅检查12.4、16.2、20.8秒静态画面；待连续检查动作和稳定性"
}
```

将 `role` 按该源区间的用途标成 establishing、action、detail、result、enjoyment 或 transition。一个文件可拆成多个不同角色区间。先查主体何时入场、动作何时发生和结束；首帧无人不能证明全条是空镜。允许缺失角色；用明确证据说明选择。`stability` 与 `motion_review` 的状态和证据写在选镜记录中，不能当作渲染器已支持的时间线字段。

### 2. 建立事件链

依据素材选择准备、到达、搭建、饮食、休息、醒来、离开等阶段。给每个主要事件写一句“观众看到什么变化”。把能构成完整小过程的镜头优先放入主线。

在 `edit-notes.md` 列出本片关键事件及其源时间、成片位置和保留理由。已拍到且承担叙事的车辆驶入、停稳、下车等到达线索优先保护；删减后要复查观众是否仍知道人物如何来到这里。到达、入夜、次晨各写一条前后镜头关系，素材未覆盖的阶段据实省略。

对缺少开头、结果或录音的事件，先寻找相关素材，再缩短、合并或省略该段。只依据真实素材和用户信息写字幕。

### 3. 粗剪

先完成正文，再判断是否需要预告。可直接以到达动作开场；需要预告时从已选镜头提取有区别的体验，15–25 秒、每镜约 1.5–2 秒仅作参考。开场承担进入环境的任务，按本期选择，避免每集套用预告、黑场标题和章节卡。

正文常以 4–8 秒作为观察起点，按动作调整。需要时保留十几秒的完整过程；可清楚省略的重复操作再压缩。用匹配动作与直接切换维持连贯。变速要有明确用途和可见连续性，保留关键操作的可读性。

遇到晃动，优先换同事件的稳镜头，再找动作成立的稳定子区间；仍不合适时缩短、合并或省略该过程。需要保留的镜头可尝试实际可用的防抖，处理后按目标画幅连续复核。片长和事件覆盖不能作为保留明显抖动的理由，预告与过渡镜头同样筛选。

在本期工作目录先渲染一段约 60–90 秒、或适合当前素材规模的代表片段，自查构图、动作和声音。默认继续完善全片；用户明确要求先看样片时才停在样片。

### 4. 声音、色彩、文字

单独检查原声。区分可听到的事实、波形量测和模型分类结果。工具无法直接听审时，完成可做的处理与画面工作，在复核记录中明确声音尚待人工听审；保持审片版状态。

保留有价值的操作声、环境底声与自然现场人声。按场景匹配声底与音量，修复已发现的突发杂音。按 [配乐与原声](references/audio/music-direction.md) 先确定每段音乐的情绪用途、进入理由与退出理由，保留有意识的连续原声段落；用 `audio-plan.json` 或 cue 表记录音乐入出点、曲目与授权、音量与淡化、需要保护的声音和实现状态。参考 Go4x4、Bancamp、Kirin Camp 的节点逻辑，具体位置由本期素材决定。缺少可用音乐时完成原声版与标记待配乐的方案。参考成片的混合音轨仅作研究。

按 [逐镜头调色](references/color-grade.md) 分析曝光、白平衡、色偏和细节，先校正单镜头与相邻镜头，再统一风格，保留昼夜光线差异。韩系 Ins 干净、清晰、简约、自然的目标按 [风格验收](references/color-grade.md#风格校准与验收) 执行：先在剪映同引擎比较同源帧，按日间阴影、日照、肤色、夜景、橙灯、晨光校准代表画面，再逐镜应用和检查。以本轮反馈与视觉改善决定力度，历史轻量批准仅作记录。默认以视频片段自身的原生“调整”参数为目标，按 [效果绑定方法](references/color-grade.md#首次原生草稿片段效果绑定) 生成，实际能力范围见 [验证记录](references/color-grade.md#本机验证边界)。仅在用户要求时建立独立调节轨道。调色采用配置生成或可用的正式批量接口；界面用于必要导入和结果复核，避免逐项点控。随附配置渲染器可生成调色预览 MP4；原生方案与 FFmpeg 预览的参数和像素效果分别验证。分别记录配置绑定、风格验收、面板读回、手工改值和保存重开的结果。HDR、Log、旋转和混合帧率先按 [运行方法](references/runtime.md) 明确处理；检查实际帧，避免仅改标签。

字幕先按 [统一排版规格](references/style-guide.md#字幕与文案) 完成日间、手部及夜间画面样张，再批量应用。正文一行优先、最多两行；字号约画面高度 2.4%，底部黑底下沿距底约 9%。字体、实际字号、位置、底色须写入工程并保存重开检查；SRT 只负责文字与时序。让正文克制可读，保留无字幕的观看空间。

### 5. 渲染和复核

按 [时间线格式](references/timeline-format.md) 记录素材 ID、源入出点、速度、音量、画幅和字幕。默认先将最终剪辑落实到可编辑剪映工程，再完成审片导出；样片及辅助渲染可使用随附渲染器。保持同一剪辑时间线与来源映射，逐项记录工程与 MP4 的实际差异。

渲染器支持的能力以时间线文档为准。工具拒绝的 HDR/旋转等素材先生成正确的规范化中间片；复杂声音衔接和调色要实际实现并复核，再在交付中标记完成。

按 [复核标准](references/review.md) 检查全片覆盖、镜头稳定性、关键动作、片头片尾、章节边界、声音、字幕和导出。稳定性在实际剪映时间线或成片中再查一遍；静态接触表及完整解码均不能替代该项。完成必要修复；区分技术检查通过、画面检查通过和实际听审通过。

## 交付

默认交付本机 Mac 剪映完整可编辑工程及草稿备份，附 FCPXML、可编辑字幕、素材路径映射、审片 MP4、`timeline.json`、`edit-notes.md`、`review.md` 和成片接触表。使用随附渲染器时一并交付 `.render.json`；从剪映导出时记录实际导出参数与版本。JSON 用于复现剪辑，镜头和字幕的独立微调在剪映工程内完成。

按 [剪映工程](references/jianying-project.md) 验证完整工程在目标版本中打开、保存、退出并重开通过，才标记工程交付成功。仅交付 MP4 或生成 XML/JSON 不能满足默认任务；剪映未安装、不可控制或导入失败时，保留已完成素材分析、时间线及审片成果，说明具体阻塞和工程尚未完成，继续处理可完成部分。

在 `edit-notes.md` 记录源根目录、每条源的相对路径/ID/大小/修改时间、成片位置、运行环境与渲染命令、章节、选镜理由、声音来源、与参考风格的取舍。配乐任务同时交付 `audio-plan.json` 或 cue 表，标记 MP4 混音、剪映独立音乐片段和实际听审各自的完成情况。中间片需记录其原始来源和变换；单独标记离线素材与未完成检查。

让下一次复核能根据成片时间找到源文件和源时间。用户反馈时只调整相关段落，保留上一版时间线和成片。源素材无需复制进交付包，但应说明重渲染依赖原文件。

首次真实素材测试后的风格修订以用户反馈和成片证据为依据。每期素材中的偶然事件留在该期记录，只有反复成立的偏好才归入本 Skill。
