## 判断与分段

以已选用的时间线片段为单位分析。检查有代表性的实际画面；光线、机位或曝光在镜头内变化时增加采样。记录源入出点、目标区间、白平衡与曝光问题、主体肤色、亮部细节、暗部噪点，以及与前后镜头的差异。直方图和像素统计辅助判断，避免仅靠数值自动匹配不同内容。

先校正单镜头的曝光、白平衡和色偏，再匹配相邻镜头。相同机位和光线可共享起始参数，但仍逐镜检查；保留白天、傍晚、夜晚、清晨的自然区别。

默认把颜色参数写入每个视频片段自身的原生“调整”面板，保持片段时序和构图。相同光线镜头可共享起始参数，分别写入各自 segment。用户明确要求独立调节轨道时，才在视频上方、文字下方建立调节片段，并核对多轨合成的作用范围；同光线且同参数的连续区间可合并。全片统一基调只能补充逐镜校正。

## 风格校准与验收

用户指定韩系 Ins 干净、清晰、简约、自然时，以中性白色、自然肤色、清楚的主体、柔和亮部和有层次的暗部为视觉目标。先解决白色偏蓝、绿黄污染和主体暗部问题，再统一相邻镜头。按实际问题幅度决定校正力度，使同源帧对比能看见目标改善；保留昼夜差异及现场暖光关系。

在剪映同版本、同引擎中比较未调色基线与当前方案的同一源帧，保持源时间、构图、画布、预览缩放和显示条件一致。记录源 ID、源时间、目标片段、参数版本与前后截图。FFmpeg 预览和参数写入记录可辅助研究，剪映风格验收以该引擎的实际前后画面为依据。

先按下列光线与主体标签挑选代表帧校准，再应用到全片逐镜检查；同一镜头可带多个标签。镜头内光线变化时补充采样，检查与前后镜头的曝光及白平衡衔接。

| 分组 | 主要校正与保留内容 |
| --- | --- |
| 日间阴影 | 校正白车、帐篷等白色偏蓝，提清主体暗部，保留林间层次 |
| 日照 | 收住白色与肤色亮部，清理绿黄污染，保留光照方向与材质 |
| 肤色 | 检查面部和手部，保持自然血色，修正绿黄或灰青偏色 |
| 夜景 | 保留黑位、灯光暖意及明暗关系，让主体可读，控制暗部噪声 |
| 橙灯 | 保留暖灯氛围，检查橙色亮部、肤色与白物，修正色块、断阶和污染 |
| 晨光 | 校正杯子、桌面和肤色的偏色，提清主体层次，保留清晨光感 |

在目标输出尺寸检查清晰度与锐化，重点看树叶、车身边缘、布料、皮肤及夜景噪声；出现晕边、碎裂或噪声放大时调整强度。先取得代表画面的方向与力度，再逐镜匹配；全片完成后复查各组及章节交界。

分别记录技术状态与风格状态。材料绑定、面板读回、实际生效及保存重开证明技术能力；同引擎同源帧比较与本轮用户反馈决定风格验收。用户认为惠州 v5 视觉上仍是微调；后续方案的代表画面复核与用户审核各自记录。[v3 调色参考](../assets/color-grade-reference.jpg) 保留为历史画面记录，当前力度以本轮目标和反馈为准。人工改过的工程先按 [交接流程](collaboration.md) 取得最新时间线。

查看本轮 [原片／v5／重开 v6 同帧对比](../assets/color-grade-v6-comparison.jpg) 与 [v6 八组代表画面](../assets/color-grade-v6-scenes.jpg)。两张均为真实剪映画面的当前候选，待用户审核；本期数值和素材仅作本期证据，不作通用预设。

## 配置生成与写入

在任务目录保存 `grade-plan.json`，关联稳定的源素材 ID、源时间、目标视频片段 ID/区间、观察证据、校正目标、风格目标、每个片段的实际参数和写入状态。参数使用目标后端已确认的名称、范围和单位；记录原生片段原参数及本轮写入字段，以及同引擎同源帧前后对比与独立的风格验收状态。尚未确认的参数保留为待实现，避免填写猜测数值。

先用白天、车内和夜景的代表片段验证材料绑定、实际画面和保存退出重开，再批量应用。另选中目标 segment 核对“调整”开关与原生面板数值，手工改值保存单独验证。只有面板数值或关键帧标记读入时记录为界面读回；工程写入、画面与持久性已通过但部分面板未查时，分别记录已完成范围及剩余检查。保留原工程版本与配置映射。GUI只承担必要的导入与结果检查；批量入口不可用时报告对应缺口，继续验证可用路径。

分别验证 FCPXML 颜色透传、首次原生草稿片段参数写入、人工修改后的最新工程回读与回写。某一路径的失败只证明该次测试结果，其他路径按各自证据判断。FCPXML 标签合法、面板有数值、关键帧标记出现都不能单独证明实际画面生效。随附配置渲染器可生成逐镜头调色 MP4；原生片段调色的完成状态单独记录。

## 首次原生草稿：片段效果绑定

此方法用于本任务自己的明文工程或已核对的交付基线。按 [工程保全](jianying-project.md#谨慎补充原生文字和淡化) 退出应用、备份并核对工程及主时间线 ID，保持根入口与主时间线入口一致。用户人工修改后按最新工程回读流程处理；用户明确确认剪辑未改、要求按原交付基线继续时，可核对基线并保留当前工程完整备份后应用，本次完整工程采用此条件。

1. 定位当前实际安装的剪映 `.app`，在 `Contents/Resources/DefaultAdjustBundle/` 中查找目标类型实际使用的目录，确认 `config.json` 及其链接资源存在；读取脚本或 shader 的实际参数，并用剪映原生画面对照确认绑定。`path` 写该目录的绝对路径。`config.name` 仅作线索，例如 `clear` 的名称为生成 ID，`light_sensation` 的名称为 `lightSensation`，无需与 `type` 相等。本期使用 `brightness`、`saturation`、`contrast`、`temperature`、`tone`、`sharpen`、`shadow`、`highlight`、`clear` 九类目录；同名版本变体分别验证，资源存在只说明可以测试。
2. 为每个目标片段的每个参数复制下列已测 `MaterialEffect` 默认字段模板，生成独立 UUID，设置 `type`、`value`、`path`，加入 `draft.materials.effects`。各片段使用独立材料 ID，便于分别修改。
3. 将效果材料 ID 加入目标 `segment.extra_material_refs`，设 `segment.enable_adjust=true`。片段的 `material_id` 继续引用原视频，时序、构图、声音及既有材料引用均保留；此绑定无需新增调节轨道。已测静态小样为 `common_keyframes=[]`，实际工程的既有关键帧保留，颜色关键帧叠加需另测。
4. 先用同源同区间的原样、去饱和、增亮等片段做对照，下表保留已测探针。完整工程的九参数应用范围见 [验证边界](#本机验证边界)；新素材按 [风格验收](#风格校准与验收) 校准代表画面和调色力度，完整范围与面板映射逐项验证。

```json
  "effect_id": "", "resource_id": "", "third_resource_id": "", "name": "",
  "type": "saturation", "sub_type": "none", "value": -1.0,
  "path": "当前安装包内DefaultAdjustBundle/saturation的绝对目录",
  "item_effect_type": 0, "category_id": "", "category_name": "",
  "platform": "all", "apply_target_type": 0, "source_platform": 0, "version": "",
  "adjust_params": [], "formula_id": "", "enable_skin_tone_correction": false,
  "algorithm_artifact_path": "", "intensity_key": "", "face_adjust_params": [],
  "exclusion_group": [], "panel_id": "", "request_id": "",
  "multi_language_current": "none", "lumi_hub_path": "", "color_correct_alg_result": ""

```

| `type` | `value` | bundle 目录 | 11.6.0 已测结果 |
| --- | --- | --- | --- |
| `saturation` | `-1.0` | `saturation` | 画面灰度，保存退出重开后保持 |
| `brightness` | `0.4` | `brightness` | 画面变亮，保存退出重开后保持；原生基础面板读回亮度 `20` |
| `shadow` | `0.4` | `shadow` | 同源原生画面对照中阴影抬起 |
| `highlight` | `-0.4` | `highlight` | 同源原生画面对照中高光压低 |

## 配置渲染预览

使用 `scripts/grading/render_grade.py`，复用原 `timeline.json`，将颜色参数放在独立 JSON。原片与剪辑时间线保持只读。颜色校正在源传递函数转换后执行；清晰度与锐化在输出尺寸执行，均先于字幕和淡入淡出。参数是 FFmpeg 单位，不能直接当作剪映滑块值，也不代表已写入原生片段调整参数。

```sh
"$CAMP_PY" "$CAMP_SKILL/scripts/grading/render_grade.py" work/timeline.json \
  --grade work/grade-plan.json --output outputs/grade-preview-v01.mp4 \
  --indices 0,1,2 --sample-seconds 5 --check
"$CAMP_PY" "$CAMP_SKILL/scripts/grading/render_grade.py" work/timeline.json \
  --grade work/grade-plan.json --output outputs/grade-preview-v01.mp4 \
  --indices 0,1,2 --sample-seconds 5 --work work/grade-preview
```

`--indices` 使用原时间线从零开始的片段索引；`--sample-seconds` 取各镜头中央片段。两项省略时渲染全片。`--bypass-grade` 生成相同裁切、色彩转换和字幕的未调色对照。有音乐的子集预览需另行明确音乐时间映射，工具会拒绝自动错位拼接。

配置骨架如下；实际需为每个入选视频镜头填写一行，明确保留原色时用 `params: {}`。黑场无需颜色参数。`timeline_sha256` 绑定原时间线文件的实际字节，防止参数错套镜头。

```json
{
  "version": 1,
  "timeline_sha256": "时间线文件的SHA-256",
  "notes": {"backend": "FFmpeg preview; native adjustment not applied"},
  "clips": [
    {
      "clip_index": 0,
      "clip_id": "镜头稳定ID",
      "params": {"eq": {"saturation": 0.96}, "unsharp": {"amount": 0.15, "size": 5}},
      "notes": {"source_in": 12.4, "source_out": 20.8, "observation": "实际画面问题与调整理由"}
    }
  ]
}
```

支持的参数：

| 参数 | 范围与含义 |
| --- | --- |
| `eq` | `brightness` −1～1；`contrast`、`saturation` 0～3；`gamma` 0.1～3；`gamma_weight` 0～1 |
| `colorbalance` | `rs/gs/bs`、`rm/gm/bm`、`rh/gh/bh` 各 −1～1；`pl` 为布尔值 |
| `curves` | `master/red/green/blue`；各为 2～17 个 `[x,y]` 点，值在 0～1，x 递增 |
| `unsharp` | `amount` 0～0.5；`size` 为 3～23 的奇数，默认 5；仅增强亮度细节 |
| `clarity` | 0～0.1，以 13×13 亮度反遮罩轻调局部反差 |

范围是工具校验边界，实际参数力度以画面问题与风格目标确定。未列参数和重复镜头索引会被拒绝。报告保存配置、后端与时间线哈希、逐镜源区间、实际滤镜和输出信息。

先检查同一源帧的前后对比，再检查渲染视频的高光、暗部和细节。惠州素材实测 `colorbalance.pl=true` 在高饱和橙灯上引入灰青色块，关闭该选项后消失；本期采用 `pl=false`。后续遇彩灯与饱和亮部时重点检查反色、断阶和肤色，按真实画面判断。
