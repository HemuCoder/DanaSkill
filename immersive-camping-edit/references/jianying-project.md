# 可编辑剪映工程

剪片任务默认交付本机 Mac 剪映可编辑完整工程，用户在剪映内预览和修改；默认省去审片 MP4 的生成与交付。用户明确只要 MP4、只分析或指定其他软件时，遵从其要求。先复用已完成的时间线、素材清单和字幕，保留每次转换及本机验证记录。

用户开始人工修改后，按 [两次交接](collaboration.md) 从最新工程继续。分别验证初次 FCPXML 颜色透传、首次原生草稿片段参数写入，以及人工修改后的最新工程回读与回写，具体实测见 [调色](color-grade.md#本机验证边界)。剪辑结构导入证据只覆盖已检查属性；最新编码草稿的回读缺口只限制后续修订。不能重新导入旧 FCPXML 覆盖人工修改。

## 证据范围

Mac 剪映专业版 11.6.0 已实际通过首页“导入 PR 或 FCP 工程”导入 FCPXML 1.9。视频片段、原素材路径、逐帧目标时间、填满裁切及原声音量可保留；黑场可表示为片段间的时间轴间隙。片段数、源数量、时长和位置均从当期清单计算。

原生片段调色、面板读回和最新工程回读的可用范围统一见 [调色能力边界](color-grade.md#本机验证边界)。按 [效果绑定方法](color-grade.md#首次原生草稿片段效果绑定) 生成独立材料与片段引用，按 [同引擎风格验收](color-grade.md#风格校准与验收) 检查视觉目标。

官方入口可参考字节扣子文档的 [视频创作](https://docs.coze.cn/cozespace_video) 与 [视频插件](https://docs.coze.cn/video-plugin)。导入前确认用户当前版本实际提供该入口；一次版本测试只证明该版本及已检查属性。

## 完整素材库

先递归盘点用户素材文件夹及子目录，再将全部可读、受支持的视频、音频和图片导入目标工程的素材库。先完成素材库，再组织时间线；未入选、重复补录与候补画面都留在素材库，便于人工增加、替换和调整。非媒体文件、损坏文件、未下载文件与不支持的格式逐项记入清单，说明处理状态。

使用目标版本实际提供的文件夹导入或批量导入入口。按源根目录与相对路径保持可追溯性；支持分组时保留原目录层次，避免同名文件混淆。核对清单中的源 ID、路径、完整时长与素材库条目，重开后检查素材仍在线可用。

素材库和时间线分别验收。FCPXML 中的 `resources/asset` 或草稿中的材料对象只证明结构记录存在；实际进入剪映素材面板、可搜索、可预览和可拖到时间线才算素材库导入完成。导入时间线若生成了新工程，在最终交付工程补齐完整素材库并重新核对。优先复用同源条目；合并重复条目仅在当前版本有已验证入口时执行，并保留已绑定时间线的引用。

核对剪映当前版本对已使用素材的标识，使用户能辨认未用素材。按实际路径和源 ID 核查使用状态，具体标识外观以当前界面为准。目标版本未显示该标识时保留完整素材库和使用映射，并说明这一项未通过；清单中的标记只作为辅助记录。

在 `media-map.json` 记录每个源 ID、根目录及相对路径、完整时长、导入状态、素材库对象标识（可取得时）、已使用的时间线片段与源区间、异常原因。图片时长按媒体类型留空。导入标识与时间线片段 ID 分别记录，同一源可对应多个片段。先在工程副本验证一条未用素材可从素材库拖入，再回到正式工程保持已定剪辑。

既有 FCPXML 测试未覆盖完整素材库、使用标识及候补拖入流程。每次在目标版本验证上述操作，完成前记录为待验证。

## 原片区间与调整余量

时间线视频直接引用完整原始文件，在片段上设置源入点、出点和目标位置。素材对象保留完整源时长；同一文件的多个片段共享源素材、分别保留源区间。保留原片在当前选段之前和之后的可用范围，让用户能拖动边缘延长或缩短、调整选用区间及从素材库换入其他素材。

FCPXML 的 `asset` 记录完整源时钟和时长，`asset-clip` 指向该源并按已选区间设置 `start/duration`。原生工程的材料路径指向原片，材料时长为完整源时长，片段的 `source_timerange` 只表示当前选段。核对非零起始时间、变速及帧率换算；可用余量按真实源时间计算。

预先裁成短文件的选段、拼接成片或调色烘焙片只用于技术诊断，默认时间线保留原片引用。分析代理与辅助渲染所需的规范化文件保存在工作目录；确需剪映代理时，仅使用已验证可关联回原片、保留全时长和时间映射的代理流程。原格式在目标软件确实无法使用时，保留原片并记录对应片段的编辑限制与待完成项，继续处理其他可用原片。

在工程副本中选择前后都有余量的片段，向两侧扩展并改变保留区间，确认可见原选段之外的真实画面、声音同步且源身份正确；多段取自同一文件时检查各自区间。到达文件头尾时记录实际可用边界。保存、退出、重开后复查，正式工程恢复已定剪点，记录实际验证范围。

## 主轨道与图层

高光、简介底片、正文与环境空镜的全部视频片段按成片顺序放在剪映主视频轨道。主轨从时间零点的高光开始；片头标题、中英简介、正文字幕保持独立文字对象，音乐与补充声音使用对应音轨。所有视频仍直接引用完整原片及相应源区间，高光与正文重复选用同一原片时共享素材、分别记录区间。

通过当前版本剪映界面的主轨标识和实际操作识别主视频轨道，记录对应轨道 ID。主时间线 ID 只标识时间线，`tracks[0]`、`type: video` 或画面能播放均不足以证明主轨归属。采用 FCPXML 时，将顺序视频排入 `spine`，导入后再确认其实际落到主轨；落在叠加轨时用当前版本支持的操作移入主轨并保持原片引用、入出点、时序和效果。

在工程副本检查拖动、修剪主轨片段及相邻片段的表现，保存重开后复查主轨归属。正式工程恢复已定剪辑与零点高光，独立文字跨剪口保持连贯。主轨归属与原片调整余量分别记录，完成当前工程的实际检查后再通过这一项。

## 转换和素材

1. 原素材保持只读，使用本机可访问的原始绝对路径。iCloud 原片已可读时直接引用，无需复制到草稿或交付包。记录路径、相对路径、大小和已有素材 ID；复用清单，避免为转换重新读取全部媒体内容或批量哈希。
2. 建立 FCPXML 1.9。分别定义目标和源 `format`，填写真实尺寸、`frameDuration`、方形像素 `paspH="1" paspV="1"`；尤其避免把 1440×1080 误当作变形宽银幕。按实际素材填写颜色信息。
3. 在每个 `asset` 内用 `media-rep kind="original-media"` 的 `src` 引用 URI。用路径库编码空格和中文；不要仅写 `asset@src`。保留原声的 `hasAudio`、声道和采样率信息。
4. 将高光、简介底片、正文和空镜按顺序平铺到 `spine` 的 `asset-clip`，黑场用 `gap`；按上节核对导入后的实际主轨道归属。原声随视频保留；仅按时间线明确的 `mute` 和增益处理。独立音乐仍按已有授权和入出点保留。
5. 用匹配版本 DTD 校验，再做包含非零源入点、源区间两侧余量、同源多段、非中央裁切、增益、黑场和字幕的小样导入。以本机保存结果和画面核对实际支持情况。

### 时序

逐片段按现有渲染器的规则量化，累计整数帧计算目标时间。不要只对全片总秒数取整，也不要用 SRT 的毫秒精度反推视频剪点。

```text
frames = max(1, round(((out - in) / speed) * output_fps))
target_start = accumulated_frames / output_fps
target_duration = frames / output_fps
accumulated_frames += frames
```

`round` 必须与该片渲染器一致，包括半帧的取整行为。FCPXML 时间写为有理秒，例如 `218/25s`。源入点对齐源视频帧；同帧率素材可用 `ceil(in * source_fps - 1e-8)`，记录相对原入点的偏差并确认源区间仍有效。混合帧率分别计算源与目标时钟，按实际变速映射核对。保存逐段源时间、目标时间和偏差映射。

### 画面和音量

- `cover` 优先测试 `adjust-conform type="fill"`；`contain` 用 `fit`。默认 fit 时可用显式缩放实现 cover，避免同时施加两次放大。
- 对 3840×2160 到 1440×1080 的方形像素画面，fill 对应原生缩放 `4/3`。水平裁切窗口按原时间线 `(scaled_width - output_width) * crop_x` 计算。
- 设缩放后溢出宽度 `overflow`，画面位移为 `(0.5 - crop_x) * overflow`。FCPXML `adjust-transform.position.x` 用 `100 * 位移像素 / output_height`；在该 Mac 版本导入后，原生 `clip.transform.x` 为 `2 * 位移像素 / output_width`。用左右偏置小样确认符号和画布归一化，垂直居中为零。
- 用 `adjust-volume amount="3dB"` 等保存原增益；原生 JSON 的线性 `volume = 10 ** (gain_db / 20)`，静音为零。转换增益不会自动复刻渲染器的最终限幅或混音处理。
- 对渲染器做过实际色彩转换的原片，抽取相同画面对比剪映。直接导入原片不能只凭相同色彩标签宣称像素一致。

## 字幕和导入后检查

从同一整数帧时间线生成 SRT。多行标题保留在同一条目内，字幕内容、顺序、开始和结束时间均与时间线对照。SRT 只携带文本和时序；字号、字体、位置、透明底和淡化须按下节补全到独立文字对象，再检查保存后的工程。仅导入 SRT 尚未完成字幕交付。

添加 SRT 前将播放头归零，再添加到字幕轨。添加后检查首条、章节中间条和末条；逐条计算 `实际开始 - 预期开始`。恒定差值表明整体偏移，先修正整轨位置，再检查多行条目是否合并为预期数量。不要只看当前播放头附近的一条字幕。

Mac 11.6 的本次 FCPXML 测试未保留音画淡化，音频 10ms 首尾去爆音也被丢弃。导入成功后仍需核对这些效果。以各期实际数量检查视频段、唯一原路径、源/目标区间、裁切、音量和文字；黑场保留为空隙时一并核对长度。

## 谨慎补充原生文字和淡化

### 字幕样式补全

文字目标以 [统一文字规格](style-guide.md#统一文字规格) 和 [编辑规格模板](../assets/intro-kit/presets.json) 为准。SRT 与 FCPXML 负责已验证的文本与时序导入，字体、字号、缩放、背景、阴影及动画在当前版本剪映中补齐为独立可编辑对象。

先在本任务测试草稿制作高光英文、中英简介及正文代表文字。片头/简介用 Montserrat、字号 10、白色、缩放 40–55%，阴影不透明度在 20–55% 内按所覆盖画面选择满足可读性的较低值，配合模糊度柔化边缘；正文用系统字体、字号 10、缩放 40%，黑底不透明度 65%、圆角 6%、高度 10%、宽度 15%。中文缺字时按字体覆盖情况使用系统中文常规字体并记录分工。所有文字入场渐显 0.8 秒、出场渐隐 0.5 秒，位置与缩放保持静态。

这些数值分别属于剪映的界面控件。先设置并读回面板值，保存对象后确认真实字段与单位，使用已验证映射批量应用。历史内部字号或渲染器画高比例无法直接代替剪映字号 10；背景宽高、圆角及缩放百分比同样需要各自映射。某个属性缺少可用的批量字段时，在原生界面完成该项并验证。

独立文字材料通过 `material_id` 绑定片段，按目标时间设置 `target_timerange`；已有文字 `content` 是包含 `text/styles` 的 JSON 字符串。复制当前版本有效对象的完整结构，更新唯一 ID、UTF-16 代码单元范围、文案和已验证样式；核对材料引用、实际字形及可编辑性。

先核对高光文字块的水平和垂直中心，再看首、中、末条正文及亮背景、手部、夜间的代表文字。检查面板值、阅读宽度、遮挡、独立显隐和黑底随字显隐，保存、退出、重开后复查。记录实际字体、中文回退、目标画幅、各项面板值、原生映射、截图及重开结果，保留每组阴影最终值。历史工程只验证过当时的独立文字与黑底；本版精确样式及动画须在目标工程重新验证，未完成属性分别记录为待完成。

### 原生补充的范围与保存

只有官方导入缺失用户所需效果时，才在任务工作目录生成补充方案。Mac 11.6 的实际任务已打开包含独立文字的完整工程，并在 GUI 检查居中标题、底部日记字幕的半透明黑底、底部英文标签，以及使用源时钟的视频透明度淡变。修正双入口后已通过官方保存、退出和重开验证，文字轨道与已检查的显隐边界保持。这是对该任务、该版本和已检查属性的证据，不构成通用草稿 API；每次交付仍需完整保存、退出、重开复核。

- 先退出剪映，备份本任务自己创建的目标草稿。只修改自己的目标工程，保留用户已有草稿；不修改 `root_meta_info.json`、不解密应用加密数据。首次交付前可在本任务明文产物验证补充结构。人工修改后的编码保存内容保持原样，取得最新工程前不以旧明文或重新导入替代；用户明确确认剪辑未改并要求按原交付基线继续时，可核对基线、完整备份当前工程后应用，记录实际依据。
- 先读取目标工程的 `Timelines/project.json`，确定主时间线 ID 和实际入口。Mac 11.6 可能同时存在根目录 `draft_info.json` 与 `Timelines/<主时间线ID>/draft_info.json`；根文件或 `load.bak` 匹配补充 JSON 仍不足以证明主时间线采用了它。仅对本任务由官方导入生成、且工程及时间线 ID 一致的草稿，在应用关闭并完整备份后保持这两个已有入口一致，保留 `Timelines/project.json` 的映射。该版本的实际样例已验证同步后保存、退出、重开保持补充内容；新任务仍需复查。
- 保留官方导入的所有视频材料和片段字段；仅增加所需文本材料、文本轨及附加效果引用。文本材料 `content` 是含 `text/styles` 的 JSON 字符串，样式范围按 UTF-16 code units 计算。字号、缩放、位置和背景依统一文字规格与目标版本已验证映射应用；高光文字块水平垂直居中，正文位于安全区。
- 音频淡化材料用 `type="audio_fade"`、`fade_type=0`、微秒 `fade_in_duration/fade_out_duration`，逐片段经 `extra_material_refs` 引用。该写法已有结构及原生模型证据，实际听审尚未完成；字段存在不等于声音效果已通过。检查每个引用都对应材料，淡化区间有效且不重叠，再实际听审切点。
- 画面透明度用 `common_keyframes` 的 `property_type="KFTypeAlpha"`，点含 `time_offset`、`values:[0或1]`、`curveType="Line"`。该版本已检查的非零源入点视频采用源时钟，即 `source_timerange.start + 局部淡变时刻 * speed`；不要写成目标时间轴绝对位置。换版本或变速用例仍先做单段验证。
- 字幕和视频是独立对象。文字动画通过当前版本实际可用的渐显/渐隐入口，或已验证只改变文字及其底板透明度的方法实现；设置 0.8 秒入场与 0.5 秒出场。视频透明度使用的字段与时钟仅适用于已测视频，文字另做验证。逐帧检查两段动画中间态，确保文字本身渐变、底片和原声正常继续，跨镜文字只执行整段首尾显隐。
- 安装补充结构后，在剪映逐项播放文字、构图和音画淡化，保存、退出、重开再查。失败时恢复本任务备份或回到官方导入版本，记录未保留效果。

## 介绍层与动效交接

根据 `intro-plan.json` 生成高光固定英文、中英主题、营地/地点、所需天气和可选物件注释，分别保留独立文字对象、ID、事实依据、时间区间、面板值和动画。高光使用一个连续文字对象覆盖高光全段；其他中英文按组对齐。必要事实待确认时，继续处理素材与正文，保留介绍项的实际状态。

`presets.json` 是剪映界面目标，`timeline.overlays` 是辅助渲染器字段，两者均需通过已验证映射才能用于原生对象。渲染器 `at/duration` 使用成片时钟，`x/y` 为归一化参数且文字 `y` 是顶部位置；直接填 `y=0.5` 只会把字块顶部放在中心。原生高光文字的中心按实际字块与画布核对，并保留每层对应关系和帧量化时序。

先在短样草稿验证一组文字独立渐显 0.8 秒、渐隐 0.5 秒和跨剪口连续性，再批量应用全部文案。核对动画中间态、充分阅读时间、对象可编辑性、字幕黑底随字淡变，以及保存重开结果。辅助预览成功仅支持其实现范围，工程中的主轨、字体面板值、背景和文字动效分别验收。

当前版本尚未完成的属性保留待完成状态，继续解决具体缺口。静态文字、烘焙图片和只淡化视频均无法满足本版独立可编辑文字及渐显隐要求。既有用户工程按 [协作交接](collaboration.md) 读取最新版本并备份，介绍层验证使用独立测试草稿。

## 交付判定

完整工程须同时包含完整素材库与全片时间线；全部视频在实际主轨道，零点高光、居中固定英文、前部中英简介及统一文字样式按 [片头文字验收](review.md#主轨道与片头文字验收) 通过。时间线保留逐镜独立的原片区间、对应原声和独立可编辑字幕；按上文验证使用标识、候补素材拖入和原片区间调整余量。在目标剪映版本打开完整工程、逐项检查、保存、退出并重开通过后，才标记可编辑工程交付成功。要求原生调色时，分别记录材料写入、实际画面、原生面板读回、手工改值保存及保存重开的结果，并按 [风格验收](color-grade.md#风格校准与验收) 独立记录视觉目标。用户风格审核、面板逐项读回和手工改值保存按实际已查与未查范围记录。每次新交付仍核对目标工程。交付实际工程位置、备份、完整素材与使用映射及复核结果，在任务目录保留实际采用的 FCPXML、SRT 等工作文件；视频导出按用户要求另行提供，注明目标剪映版本、外部原片依赖、源入点量化差异和未完成的听审或效果检查。仅有 XML/JSON 合法、片段计数正确或小样打开时，继续标记为待本机验证。

目标剪映不可用或完整工程验证未通过时，保留时间线、转换文件与素材映射，在交付记录中明确“工程未完成”及具体阻塞，继续处理可完成部分。工程交付成功以本机实际操作和重开验证为准。
