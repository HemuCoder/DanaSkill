# 可编辑剪映工程

导航：[转换和素材](#转换和素材) · [字幕和导入后检查](#字幕和导入后检查) · [字幕样式补全](#字幕样式补全) · [交付判定](#交付判定)

剪片任务默认以本机 Mac 剪映可编辑完整工程为主交付，同时提供审片 MP4。用户明确只要 MP4、只分析或指定其他软件时，遵从其要求。先复用已完成的时间线、素材清单和字幕，保留每次转换及本机验证记录。

用户开始人工修改后，按 [两次交接](collaboration.md) 从最新工程继续。分别验证初次 FCPXML 颜色透传、首次原生草稿片段参数写入，以及人工修改后的最新工程回读与回写，具体实测见 [调色](color-grade.md#本机验证边界)。剪辑结构导入证据只覆盖已检查属性；最新编码草稿的回读缺口只限制后续修订。不能重新导入旧 FCPXML 覆盖人工修改。

## 证据范围

Mac 剪映专业版 11.6.0 已实际通过首页“导入 PR 或 FCP 工程”导入 FCPXML 1.9。视频片段、原素材路径、逐帧目标时间、填满裁切及原声音量可保留；黑场可表示为片段间的时间轴间隙。片段数、源数量、时长和位置均从当期清单计算。

本期 v6 完整工程已对 83 个视频片段配置 747 个九类原生效果材料，保留 12 条字幕、651.12 秒与 4:3 画幅；八个代表帧静态复核无明显异常。保存退出重开后，C1370 九项原生面板值再次读回，日间及手部代表画面保持，完整保存快照通过 ZIP 检查。风格待用户批准；GUI 手工改值保存、全镜头面板值及完整参数范围尚未全面验证，本轮未导出、连续播放全片或听审。人工修改后编码工程回读仍未解决。按 [效果绑定方法](color-grade.md#首次原生草稿片段效果绑定) 复用材料与片段引用关系，按 [同引擎风格验收](color-grade.md#风格校准与验收) 判断视觉目标。

官方入口可参考字节扣子文档的 [视频创作](https://docs.coze.cn/cozespace_video) 与 [视频插件](https://docs.coze.cn/video-plugin)。导入前确认用户当前版本实际提供该入口；一次版本测试只证明该版本及已检查属性。

## 转换和素材

1. 原素材保持只读，使用本机可访问的原始绝对路径。iCloud 原片已可读时直接引用，无需复制到草稿或交付包。记录路径、相对路径、大小和已有素材 ID；复用清单，避免为转换重新读取全部媒体内容或批量哈希。
2. 建立 FCPXML 1.9。分别定义目标和源 `format`，填写真实尺寸、`frameDuration`、方形像素 `paspH="1" paspV="1"`；尤其避免把 1440×1080 误当作变形宽银幕。按实际素材填写颜色信息。
3. 在每个 `asset` 内用 `media-rep kind="original-media"` 的 `src` 引用 URI。用路径库编码空格和中文；不要仅写 `asset@src`。保留原声的 `hasAudio`、声道和采样率信息。
4. 将顺序镜头平铺到 `spine` 的 `asset-clip`，黑场用 `gap`。原声随视频保留；仅按时间线明确的 `mute` 和增益处理。独立音乐仍按已有授权和入出点保留。
5. 用匹配版本 DTD 校验，再做包含非中央裁切、增益、黑场和字幕的小样导入。以本机保存结果和画面核对实际支持情况。

### 时序

逐片段按现有渲染器的规则量化，累计整数帧计算目标时间。不要只对全片总秒数取整，也不要用 SRT 的毫秒精度反推视频剪点。

```text
frames = max(1, round(((out - in) / speed) * output_fps))
target_start = accumulated_frames / output_fps
target_duration = frames / output_fps
accumulated_frames += frames
```

`round` 必须与该片渲染器一致，包括半帧的取整行为。FCPXML 时间写为有理秒，例如 `218/25s`。源入点对齐源视频帧；同帧率素材可用 `ceil(in * source_fps - 1e-8)`，记录相对原入点的偏差并确认源区间仍有效。混合帧率分别计算源与目标时钟，按实际变速映射核对。保存逐段源时间、目标时间和偏差映射。

### 画面和音量

- `cover` 优先测试 `adjust-conform type="fill"`；`contain` 用 `fit`。默认 fit 时可用显式缩放实现 cover，避免同时施加两次放大。
- 对 3840×2160 到 1440×1080 的方形像素画面，fill 对应原生缩放 `4/3`。水平裁切窗口按原时间线 `(scaled_width - output_width) * crop_x` 计算。
- 设缩放后溢出宽度 `overflow`，画面位移为 `(0.5 - crop_x) * overflow`。FCPXML `adjust-transform.position.x` 用 `100 * 位移像素 / output_height`；在该 Mac 版本导入后，原生 `clip.transform.x` 为 `2 * 位移像素 / output_width`。用左右偏置小样确认符号和画布归一化，垂直居中为零。
- 用 `adjust-volume amount="3dB"` 等保存原增益；原生 JSON 的线性 `volume = 10 ** (gain_db / 20)`，静音为零。转换增益不会自动复刻渲染器的最终限幅或混音处理。
- 对渲染器做过实际色彩转换的原片，抽取相同画面对比剪映。直接导入原片不能只凭相同色彩标签宣称像素一致。

## 字幕和导入后检查

从同一整数帧时间线生成 SRT。多行标题保留在同一条目内，字幕内容、顺序、开始和结束时间均与时间线对照。SRT 只携带文本和时序；字号、字体、位置、透明底和淡化须按下节补全到独立文字对象，再检查保存后的工程。仅导入 SRT 尚未完成字幕交付。

添加 SRT 前将播放头归零，再添加到字幕轨。添加后检查首条、章节中间条和末条；逐条计算 `实际开始 - 预期开始`。恒定差值表明整体偏移，先修正整轨位置，再检查多行条目是否合并为预期数量。不要只看当前播放头附近的一条字幕。

Mac 11.6 的本次 FCPXML 测试未保留音画淡化，音频 10ms 首尾去爆音也被丢弃。导入成功后仍需核对这些效果。以各期实际数量检查视频段、唯一原路径、源/目标区间、裁切、音量和文字；黑场保留为空隙时一并核对长度。

## 谨慎补充原生文字和淡化

### 字幕样式补全

正文按 [排版规格](style-guide.md#字幕与文案) 落实小号、常规字重、白字、贴字黑色半透明底与底部留白。SRT 与 FCPXML 的文本/时序导入，不保证这些属性透传。先在本任务测试草稿补齐样式，验证后再应用完整工程；采用可用配置或批量接口处理，界面用于必要导入、样张校准与复核。

Mac 11.6 已测试的日记文字材料背景片段如下，须合入与目标版本一致的完整独立文字材料，并绑定对应文字片段；它不是可直接导入的独立文件或渲染时间线字段：

```json
{
  "check_flag": 23,
  "background_style": 1,
  "background_color": "#000000",
  "background_alpha": 0.5294117647058824,
  "background_round_radius": 0.0,
  "background_height": 0.14,
  "background_width": 0.14,
  "background_horizontal_offset": 0.0,
  "background_vertical_offset": 0.0
}
```

该版本已有文字 `content` 中 `styles` 的区间、白色 `fill`、`bold:false`、`italic:false`、`strokes:[]`，材料为 `type:"text"`、`alignment:1`；对应独立文字片段通过 `material_id` 绑定材料，按目标时间设置 `target_timerange`。复制当前版本有效文字对象的完整结构，更新唯一 ID、UTF-16 代码单元长度、文字内容和样式，检查材料引用及字形。字体要明确设置成实际可用的无衬线家族并在画面确认。

历史测试的内部正文字号为 `5.5`，底部片段 `clip.transform.y=-0.82`，只证明当期旧版文字可编辑且黑底生效。**这两个数值不代表新版约 26 px、距底 9% 的视觉目标。** 本轮缩小与留白规格已在随附渲染器验证；原生剪映须在目标版本另做样张校准，按导出画面中的文字高度、黑底外沿和主体遮挡测量。不同版本的背景宽高与字体字段仍先小样验证。

首、中、末条正文及日间、手部、夜间至少各一例，检查字体/字重、尺寸、黑底透明度、贴字宽度、位置、行数、显隐和可编辑性；同一条可覆盖多项。保存、退出、重开后重新检查。记录 `caption_style` 的实际字体、目标画幅、原生参数、已查截图与重开结果。背景或字体未保留时继续修复，并标记“字幕样式待完成”；审片 MP4 中烧录样式生效，不能替代可编辑工程里的样式验收。

### 原生补充的范围与保存

只有官方导入缺失用户所需效果时，才在任务工作目录生成补充方案。Mac 11.6 的实际任务已打开包含独立文字的完整工程，并在 GUI 检查居中标题、底部日记字幕的半透明黑底、底部英文标签，以及使用源时钟的视频透明度淡变。修正双入口后已通过官方保存、退出和重开验证，文字轨道与已检查的显隐边界保持。这是对该任务、该版本和已检查属性的证据，不构成通用草稿 API；每次交付仍需完整保存、退出、重开复核。

- 先退出剪映，备份本任务自己创建的目标草稿。只修改自己的目标工程，保留用户已有草稿；不修改 `root_meta_info.json`、不解密应用加密数据。首次交付前可在本任务明文产物验证补充结构。人工修改后的编码保存内容保持原样，取得最新工程前不以旧明文或重新导入替代；用户明确确认剪辑未改并要求按原交付基线继续时，可核对基线、完整备份当前工程后应用，记录实际依据。
- 先读取目标工程的 `Timelines/project.json`，确定主时间线 ID 和实际入口。Mac 11.6 可能同时存在根目录 `draft_info.json` 与 `Timelines/<主时间线ID>/draft_info.json`；根文件或 `load.bak` 匹配补充 JSON 仍不足以证明主时间线采用了它。仅对本任务由官方导入生成、且工程及时间线 ID 一致的草稿，在应用关闭并完整备份后保持这两个已有入口一致，保留 `Timelines/project.json` 的映射。该版本的实际样例已验证同步后保存、退出、重开保持补充内容；新任务仍需复查。
- 保留官方导入的所有视频材料和片段字段；仅增加所需文本材料、文本轨及附加效果引用。文本材料 `content` 是含 `text/styles` 的 JSON 字符串，样式范围按 UTF-16 code units 计算。字号、位置和半透明底依目标版本小样校准，保留时间线指定的 top/center/bottom。
- 音频淡化材料用 `type="audio_fade"`、`fade_type=0`、微秒 `fade_in_duration/fade_out_duration`，逐片段经 `extra_material_refs` 引用。该写法已有结构及原生模型证据，实际听审尚未完成；字段存在不等于声音效果已通过。检查每个引用都对应材料，淡化区间有效且不重叠，再实际听审切点。
- 画面透明度用 `common_keyframes` 的 `property_type="KFTypeAlpha"`，点含 `time_offset`、`values:[0或1]`、`curveType="Line"`。该版本已检查的非零源入点视频采用源时钟，即 `source_timerange.start + 局部淡变时刻 * speed`；不要写成目标时间轴绝对位置。换版本或变速用例仍先做单段验证。
- 字幕和视频是独立对象。原渲染器在字幕叠加后统一淡化，单独淡视频会留下文字。本期未取得文字 `KFTypeAlpha` 或 `GlobalAlpha` 执行的可靠证据，旧主时间线可能影响观察，不能据此判定这些字段不受支持。未验证字段不作效果承诺；可按视频实际淡入结束和淡出开始调整文字可见区间，并移除未确认的文字关键帧。记录相对原字幕时序的有意改动，检查信息仍完整且没有悬字。
- 安装补充结构后，在剪映逐项播放文字、构图和音画淡化，保存、退出、重开再查。失败时恢复本任务备份或回到官方导入版本，记录未保留效果。

## 交付判定

完整工程须覆盖全片，保留逐镜独立片段、对应原声和独立可编辑字幕。在目标剪映版本打开完整工程、逐项检查、保存、退出并重开通过后，才标记可编辑工程交付成功。要求原生调色时，分别记录材料写入、实际画面、原生面板读回、手工改值保存及保存重开的结果，并按 [风格验收](color-grade.md#风格校准与验收) 独立记录视觉目标。用户风格审核、面板逐项读回和手工改值保存按实际已查与未查范围记录。每次新交付仍核对目标工程。交付实际工程位置、审片 MP4、FCPXML、SRT、素材映射及复核结果，注明目标剪映版本、外部原片依赖、源入点量化差异和未完成的听审或效果检查。仅有 XML/JSON 合法、片段计数正确或小样打开时，继续标记为待本机验证。

目标剪映不可用或完整工程验证未通过时，保留时间线、转换文件、素材映射和已生成的审片 MP4，在交付记录中明确“工程未完成”及具体阻塞。MP4 可作为中间成果交接，默认工程交付仍待完成。
